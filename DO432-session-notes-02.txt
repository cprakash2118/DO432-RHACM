     - Other certified k8s distributions (Approved by CNCF)

Point-02-)
  Roles of RHACM's components:-
  A) RHACM HUB cluster 
     - This is the OpenShift cluster where RHACM is installed.
     - As control plane for multi-cluster management.

  B) Multicluster Engine Operator (MCE):-
     - Provides the "cluster lifecycle" framework that RHACM uses.
     - RHACM UI triggers actions, MCE orchestrates.

  c) Hive Operator (Provisionining engine).
     - Hive is the provisioning controller for most supported provides.
     - When you create cluster in RHACM, Hive create the real cloud resources and install OpenShift.

  D) Assisted installer (For some on-prem flows):-
     - FOr on-pre, provisioning patterns, the flow differs from pure cloud.
     - RHACM uses platform integrations + assisted install capabilities instead of onlu "Hive".

Point-05-) Creating a Cluster - What RHACM actually create behind the scenes:-
 
 
  RHOSPv16/17 [Controller,Compute,Storage,ComputeHCI]
  Controller [3 nodes]
  Compute    [40 nodes]
  Storage    [3 nodes cluster - CEP]
  
  RHOSPv18 -> [Controller running on RHOCP]  -> Private Cloud. CL170
  Controller [3 nodes] - Running now on OCP cluster.
  Compute    [40 nodes]
  Storage    [3 nodes cluster - CEP]
  
  
  
  - When you click "Create cluster" in the console (RHACM (via MCE) relies on HIVE.
  
  - *** RHACM create a "ClusterDeployment" CR (Custom Resource).
  That "ClusterDeployment":
  - Describes the desired cluster (name, BaseDomain, provider, region, credentials).
  - POints to an OpenShift release via an image reference [Select RHOCP version image]
  - point to install config/ssh key/ pull secret reference
  
  Hive watches the ClusterDeployment and perform the install
  
  - Why "ClusterImageSet" exist?
    - ClusterImageSet = "Approved OpenShift installer image catalog"
	- Immutable reference 
	- Decopling installer from cluster definitions.
